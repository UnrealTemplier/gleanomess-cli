GleanoMess v0.1.1: Архитектура и Анализ Исходного Кода

Исчерпывающее техническое руководство, разбор исходного кода строка за строкой, инженерный глоссарий, архитектурный конвейер и практическое пособие уровня Senior → Junior для версии 0.1.1 утилиты GleanoMess.

💡 Как устроена эта документация

Вся кодовая база GleanoMess написана на чистом, идиоматическом Go (без CGO, без тяжелых фреймворков, без скрытой магии). В каждом разделе вы найдете: строку исходного кода, подробное объяснение, почему она написана именно так, и специальный блок с разбором базовых и продвинутых терминов компьютерных наук (Computer Science).

Что нового в версии 0.1.1 (Архитектурные Улучшения)

Ключевые инженерные изменения в v0.1.1:

  • Обновление Toolchain: Переход на Go 1.27.1 как базовый компилятор в go.mod, CI и сборочных скриптах.
  • Лицензирование: Проект переведен на максимально permissive лицензию 0BSD (BSD Zero Clause License).
  • Кроссплатформенный GitHub Actions CI: Автоматизированное тестирование на трех операционных системах: Linux amd64 (с детектором гонок -race), Windows amd64 и macOS arm64.
  • Атомарная Дедупликация (Atomic Finalize): Решена проблема race condition между конкурентными горутинами при одновременном скачивании одинаковых файлов через метод ContentTracker.Finalize с автоматическим откатом транзакции (rollback).
  • Цепочки Фолбэков в Слотах (Fallback Chains): Кандидаты группируются в логические слоты (Slot). Ранжирование задает строгий порядок попыток: при падении приоритетного кандидата (HTTP 4xx/5xx, битый файл, отсечение по размеру) автоматически совершается попытка скачать следующий кандидат. При успехе дальнейшие загрузки для слота прекращаются.
  • Защита от усеченных потоков (Truncation Safety): Чтение через io.LimitReader(body, maxBytes+1) на границе ~500 MiB гарантирует выявление переполнения и удаление временного файла без сохранения битых картинок.
  • Гарантированное закрытие сокетов: Все пути владения http.Response.Body гарантированно закрываются, включая редиректы, постоянные ошибки и ретраи.

1. Архитектурный конвейер (Data Pipeline v0.1.1)

Главная задача утилиты — взять один HTTP(S) URL веб-страницы, разобрать статический HTML без использования тяжелых браузерных движков, найти все растровые изображения, эвристически сформировать цепочки кандидатов от оригиналов к миниатюрам, параллельно скачать их без пережатия байт и аккуратно сохранить на диск с атомарной дедупликацией.

2. 16 Непреложных Инженерных Инвариантов GleanoMess

⚠️ Инварианты Архитектуры (Invariants - DO NOT VIOLATE)
  1. Никакого пережатия (Zero Recompression): Байт в байт сохранять исходный поток данных, полученный по HTTP. Запрещено модифицировать или перекодировать пиксели.
  2. Не доверять расширениям файлов: Расширение в URL может быть ложным. Формат валидируется строго по сигнатурам (Magic Bytes) и декодерам заголовков; расширение — лишь запасной вариант.
  3. Разрешение относительных ссылок против базового URL: Относительные пути разрешаются относительно финального URL страницы или тега <base href> с обязательным отсечением фрагментов (#...).
  4. Фильтр размера — это max(width, height) >= N: Если максимальная сторона изображения не меньше N, файл принимается.
  5. Никакого полного декодирования в RAM: Для проверки геометрии используется image.DecodeConfig и разбор боксов заголовков, чтобы не расходовать сотни мегабайт на пиксельные карты.
  6. Запись во временные файлы (.tmp) перед финализацией: Ни один поврежденный или отсеянный файл не должен получить финальное имя на диске.
  7. Потокобезопасная дедупликация URL: Каждый нормализованный URL запрашивается по сети не более 1 раза.
  8. Атомарная дедупликация контента с финализацией: Проверка хеша, выделение имени файла и переименование производятся атомарно в критической секции. При сбое сохранения состояние трекера откатывается.
  9. Ранжированные кандидаты образуют цепочку фолбэков (Fallback Chain): Ранжирование задает строгий порядок попыток в слоте. Если приоритетный кандидат упал или не прошел фильтр, пробуется следующий кандидат.
  10. Никаких лишних загрузок после успеха: Как только кандидат в слоте успешно сохранен или опознан как дубликат, обработка слота немедленно завершается.
  11. JSON-LD извлекает только семантические поля изображений: Извлекаются только свойства image, contentUrl, thumbnailUrl, ImageObject, @graph. Произвольные строки (заголовки, имена, авторы) игнорируются.
  12. Никакого тихого принятия усеченных файлов: При превышении лимита размера (~500 MiB) загрузка прерывается с ошибкой, временный файл удаляется и не финализируется.
  13. Гарантированное закрытие тел HTTP-ответов: Каждый Response.Body гарантированно закрывается на всех путях выполнения, включая ошибки 4xx, редиректы и повторные попытки.
  14. Изоляция сбоев: Ошибка на одном изображении инкрементирует счетчик ошибок, но не прерывает работу со всей страницей.
  15. Каталог по умолчанию — рядом с бинарником: Папка создается по пути filepath.Dir(exePath)/<host>/ с разрешением симлинков.
  16. Никакого несанкционированного расширения Scope: Не превращать утилиту в браузерный движок или распределенный краулер.

3. Инженерный Глоссарий (База Терминов)

📖 Термин: DOM (Document Object Model) и древовидный обход через golang.org/x/net/html

DOM (Объектная Модель Документа) — это представление структуры HTML-документа в памяти в виде графа/дерева. Каждый узел (html.Node) содержит ссылки на FirstChild, NextSibling и атрибуты. В отличие от регулярных выражений, DOM-парсер сохраняет иерархический контекст: например, мы знаем, что тег <img> находится внутри ссылки <a href> или контейнера <picture>.

⚙️ Deep Dive: Атомарная Финализация (Atomic Check-and-Save) и TOCTOU Race Condition

В многопоточном приложении возникает классическая проблема TOCTOU (Time-of-Check to Time-of-Use): если горутина A проверяет «файл с таким SHA-256 уже есть?» и получает «нет», а в этот же момент горутина B скачивает то же самое изображение из другого URL, обе горутины решат сохранить файл и создадут дубликаты pic.jpg и pic_2.jpg на диске.

В v0.1.1 метод ContentTracker.Finalize выполняет двойную проверку внутри мьютекса (Double-Checked Locking). Проверка хеша, выделение имени файла и переименование os.Rename происходят в атомарной критической секции. Если функция сохранения возвращает ошибку, хеш не регистрируется (транзакционный откат).

📖 Термин: Magic Bytes (Сигнатуры Файлов) и многоуровневая валидация

Magic Bytes (Магические Байты) — уникальная последовательность байт в начале файла, стандартизированная спецификацией формата для его мгновенной идентификации операционными системами независимо от расширения файла:

  • PNG: 8 байт: 89 50 4E 47 0D 0A 1A 0A.
  • JPEG: 0xFF 0xD8 0xFF (маркер SOI).
  • GIF: ASCII-строка GIF87a или GIF89a.
  • WebP: Контейнер RIFF: RIFF....WEBP.
  • BMP: Символы BM (0x42 0x4D).
  • TIFF: II*\x00 (Little-Endian) или MM\x00* (Big-Endian).
  • AVIF: Бокс ftyp с совместимым брендом avif.
⚙️ Deep Dive: Формат ISOBMFF и структура боксов AVIF (Box/Atom)

AVIF базируется на стандарте ISOBMFF (ISO/IEC 14496-12). Файл состоит из иерархических блоков (Box). Каждый бокс имеет 4 байта длины (Big-Endian uint32) и 4 байта FourCC типа (например, ftyp, meta, ispe).

Размеры картинки хранятся в боксе ispe (Image Spatial Extents Property) внутри meta → iprp → ipco → ispe в виде двух 32-битных чисел ширины и высоты. Парсер GleanoMess извлекает эти размеры за доли миллисекунды из первых нескольких килобайт файла без декодирования AV1-видеопотока.

📖 Термин: Bounded Worker Pool (Ограниченный пул воркеров)

Паттерн, предотвращающий неконтролируемое потребление ресурсов. Если страница содержит 500 картинок, запуск 500 одновременных горутин приведет к исчерпанию файловых дескрипторов и блокировке по IP со стороны веб-сервера. GleanoMess запускает фиксированное число горутин (по умолчанию 4, флаг --workers N), читающих задачи из одного канала.

💡 Совет для Go-джуниора: Graceful Shutdown и context.Context

Связка signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM) переводит контекст в состояние отмены при нажатии Ctrl+C. Все HTTP-запросы мгновенно прерываются, воркеры выходят из цикла, а отложенные defer os.Remove(tmpPath) стирают временные файлы, не оставляя мусора на диске.

📖 Термин: Exponential Backoff и Jitter

При получении временных ошибок (HTTP 429, 503, 502, 504) задержка между повторными попытками увеличивается экспоненциально: Base * 2^attempt. Случайный Jitter (0–100 мс) предотвращает проблему «громоподобного стада» (Thundering Herd), когда сотни клиентов синхронно обращаются к серверу в одну и ту же миллисекунду.

⚙️ Deep Dive: Атомарный Rename в POSIX-файловых системах

Скачивание выполняется в файл .gleanomess-*.tmp в целевом каталоге. Системный вызов rename(2) атомарно подменяет указатель в каталоге: сторонний процесс никогда не увидит недокачанный или усеченный файл — на диске появляется только полностью проверенное изображение.

Вычисление Каталога Сохранения: resolveTargetDir

Каталог для сохранения картинок по умолчанию вычисляется рядом с физическим бинарником, с предварительным удалением префикса www. и санитизацией спецсимволов имени хоста:

cmd/gleanomess/main.go — resolveTargetDir 
func resolveTargetDir(customBaseDir string, u *url.URL) (string, error) {
    host := u.Hostname()
    if strings.HasPrefix(strings.ToLower(host), "www.") {
        host = host[4:]
    }
    sanitizedHost := invalidHostCharsRegex.ReplaceAllString(host, "_")
    // Вычисляем путь к бинарнику с разрешением симлинков
    exePath, _ := os.Executable()
    realPath, err := filepath.EvalSymlinks(exePath)
    if err == nil { exePath = realPath }
    return filepath.Join(filepath.Dir(exePath), sanitizedHost), nil
}

5. Разбор Кода: Скрейпер и Логические Слоты (internal/scraper)

В версии 0.1.1 скрейпер группирует найденные кандидаты в логические слоты (Slot). Слот соответствует одному визуальному месту под изображение на странице и содержит упорядоченный список URL с приоритетами.

internal/scraper/scraper.go — Структура Slot и Candidate 
type Candidate struct {
    RawURL      string
    ResolvedURL *url.URL
    Source      CandidateSource
    Priority    int
    Descriptor  string // "1600w" или "2x"
}

type Slot struct {
    Candidates []*Candidate
}

func (s *Slot) Best() *Candidate {
    if len(s.Candidates) == 0 { return nil }
    return s.Candidates[0]
}

Семантическая Фильтрация JSON-LD

Согласно Инварианту 11, из JSON-LD разрешено извлекать только явно предназначенные для картинок поля. Произвольные текстовые строки (например, @context, headline, author, name) никогда не должны интерпретироваться как ссылки на изображения:

internal/scraper/scraper.go — Рекурсивный обход JSON-LD 
func extractJSONLDSlots(v any, baseURL *url.URL, addSlot func(*Slot)) {
    switch val := v.(type) {
    case map[string]any:
        // 1. Рекурсия в @graph
        if graph, ok := val["@graph"]; ok { extractJSONLDSlots(graph, baseURL, addSlot) }
        // 2. Только явные семантические поля картинок
        if img, ok := val["image"]; ok { extractJSONLDImageField(img, baseURL, 30, addSlot) }
        if contentURL, ok := val["contentUrl"]; ok { extractJSONLDImageField(contentURL, baseURL, 32, addSlot) }
        if thumbURL, ok := val["thumbnailUrl"]; ok { extractJSONLDImageField(thumbURL, baseURL, 28, addSlot) }
        // 3. Если тип объекта - ImageObject, проверяем url
        if isImageObjectType(val["@type"]) {
            if u, ok := val["url"]; ok { extractJSONLDImageField(u, baseURL, 32, addSlot) }
        }
        // 4. Рекурсия ТОЛЬКО во вложенные объекты или массивы (строки игнорируются!)
        for k, child := range val {
            switch child.(type) {
            case map[string]any, []any:
                extractJSONLDSlots(child, baseURL, addSlot)
            }
        }
    }
}

6. Разбор Кода: Загрузчик и Цепочки Фолбэков (internal/downloader)

Центральным новшеством v0.1.1 стала функция processSlot, реализующая отказоустойчивое исполнение цепочки фолбэков для каждого визуального слота.

internal/downloader/downloader.go — processSlot Fallback Chain 
func (d *Downloader) processSlot(ctx context.Context, slot *scraper.Slot, index, total int) *ItemResult {
    var lastRes *ItemResult

    for candIdx, cand := range slot.Candidates {
        // 1. Попытка обработки очередного кандидата по приоритету
        res := d.processCandidate(ctx, cand, index, total)
        lastRes = res

        // 2. Если успешно скачан — СЛОТ ЗАВЕРШЕН, низшие кандидаты НЕ скачиваются!
        if res.Status == StatusDownloaded {
            return res
        }

        // 3. Если этот файл или URL уже скачан ранее — слот удовлетворен
        if res.Status == StatusDuplicate {
            return res
        }

        // 4. Ошибка или отсев по размеру: если есть следующий кандидат — ФОЛБЭК!
        if candIdx+1 < len(slot.Candidates) && d.options.Verbose {
            d.reportFallback(index, total, cand, res, slot.Candidates[candIdx+1])
        }
    }

    return lastRes
}

Защита от Переполнения и Усеченных Загрузок (Truncation Safety)

Согласно Инварианту 12, нельзя просто вызывать io.LimitReader(body, maxBytes): если сервер передаст файл размером 600 МБ, такой ридер просто молча обрежет его на 500 МБ и создаст битую недокачанную картинку. В GleanoMess v0.1.1 считывается maxBytes + 1:

internal/downloader/downloader.go — Overflow Detection 
limitedReader := io.LimitReader(reqResult.Response.Body, maxBytes+1)
n, copyErr := io.Copy(writer, limitedReader)
_ = tmpFile.Close()

if n > maxBytes {
    // Размер превысил безопасный лимит! Отбрасываем файл.
    res.Status = StatusError
    res.Error = fmt.Errorf("image exceeds internal download size limit")
    return res
}

7. Разбор Кода: Атомарная Дедупликация (internal/dedup)

Пакет internal/dedup обеспечивает потокобезопасную дедупликацию нормализованных URL и атомарную дедупликацию файлов по хешу SHA-256.

internal/dedup/dedup.go — Метод Finalize с защитой от гонок 
func (c *ContentTracker) Finalize(hashHex string, saveFn func() (string, error)) (string, bool, error) {
    c.mu.Lock()
    defer c.mu.Unlock()

    // 1. Повторная проверка внутри мьютекса (Double-Checked Locking)
    if existing, ok := c.hashes[hashHex]; ok {
        return existing, true, nil
    }

    // 2. Вызов функции сохранения (выделение уникального имени и atomic rename)
    finalFilename, err := saveFn()
    if err != nil {
        // Транзакционный откат: хеш НЕ сохраняется в трекере!
        return "", false, err
    }

    // 3. Успешная регистрация
    c.hashes[hashHex] = finalFilename
    return finalFilename, false, nil
}

8. Разбор Кода: Форматы, Размеры и Имена Файлов

Пакет internal/imageinfo валидирует растровые форматы и считывает геометрию без загрузки тяжелых пиксельных матриц в RAM.

⚙️ Почему SVG, ICO и HTML отсекаются немедленно?

В соответствии с Инвариантом 2 и целями проекта GleanoMess (сохранение только растровых изображений), векторный формат SVG (XML-код) и значки ICO (содержащие мультииконки) отсекаются еще до вызова декодеров. Ответы с MIME-типом text/html (часто возвращаемые при 404/блоках вместо картинок) также мгновенно бракуются.

Санитизация Имен Файлов и Windows Reserved Devices

Файл internal/naming/naming.go очищает имена файлов от управляющих и запрещенных символов (\ / : * ? " < > |), а также защищает от сбоев на платформе Windows при встрече зарезервированных имен устройств:

internal/naming/naming.go — Windows Reserved Device Guard 
var windowsReservedNames = map[string]bool{
    "CON": true, "PRN": true, "AUX": true, "NUL": true,
    "COM1": true, "COM2": true, "COM3": true, "COM4": true,
    "LPT1": true, "LPT2": true, "LPT3": true, "LPT4": true,
}

func SanitizeFilename(name string) string {
    base := filepath.Base(filepath.ToSlash(name))
    base = invalidCharsRegex.ReplaceAllString(base, "_")
    cleanName := strings.TrimSuffix(base, filepath.Ext(base))
    if windowsReservedNames[strings.ToUpper(cleanName)] {
        base = "_" + base
    }
    return base
}

10. Уроки и Паттерны для Go-Джуниоров

💡 Урок 1: Опасность defer в циклах

Никогда не пишите defer resp.Body.Close() внутри цикла for. Инструкция defer выполняется не на следующей итерации цикла, а только при выходе из окружающей функции! В цикле на 1000 элементов программа исчерпает лимит сокетов ОС. Выносите тело итерации в отдельную функцию (например, processCandidate), и тогда defer сработает мгновенно по завершении обработки одного элемента.

💡 Урок 2: Разрешение симлинков через filepath.EvalSymlinks

Если бинарник запущен через симлинк (например, /usr/local/bin/gleanomess -> /opt/gleanomess/gleanomess), наивный os.Executable() вернет путь к симлинку, и папка сайта создастся в системном каталоге. Вызов filepath.EvalSymlinks вычисляет настоящий физический путь.

💡 Урок 3: Мокирование HTTP в тестах через httptest.Server

Никогда не тестируйте скрейпер или загрузчик, обращаясь к реальным сайтам в интернете (они могут изменить разметку, упасть или заблокировать CI). Используйте httptest.NewServer(http.HandlerFunc(...)) — это полноценный локальный веб-сервер Go, поднимающийся на случайном порту за миллисекунды.
